## 原生 OCR 对比度复核

2026-11-09，原生 CI [42633295464](https://github.com/RollandXD/qingsongxiong/actions/runs/42633295464) 中：

- `testContrastTokenProbe` 的七组相同色板文字全部通过，包括玻璃与渐变。
- 首页和详情的短中文、百分比及实时倒计时仍随机被报告 `Contrast failed`，包括深色背景上的白色大标题。
- 导出图片中浅色次级文字为 `#353A34`，局部背景约 `#FAF6F3` / `#FCF9F7`，WCAG 对比度实测约 10.8–11.1:1；不是继续改深颜色可以解决的问题。

`UITests/RenderedAccessibilityAudit.swift` 保留原生审计。当且仅当原生报告 contrast 时，对**该元素的当前真实截图**复核：

1. 元素必须完全位于屏幕内，可取得实际图像；否则不豁免。
2. 裁图中必须存在足量语义墨色核心像素（每通道偏差 ≤5；至少 24 个且占裁图 1%）；不拿图表色、抗锯齿边缘或任意黑点代替文字。
3. 以裁图主导背景颜色量化估算局部背景，按照 WCAG sRGB 线性化与相对亮度公式计算。
4. 所有识别到的墨色核心像素与背景的最低对比度必须 ≥4.5:1，满足后才将该条原生 OCR 问题视为已复核，并输出 `BEAR_RENDERED_CONTRAST` 实测证据。
5. 未识别到墨色、对比度不足、其他审计类型均继续失败。不按元素名称、主题或测试名无条件跳过。

`RenderedContrastTests` 使用真实 raster 图验证可读文本通过、低对比文本和非语义浅灰文本被拒绝。此复核不是完整 OCR 或 WCAG 合规认证；文字截断、滚动可达性仍由原生测试及人工截图检查覆盖。

占位破折号为装饰，不单独进入无障碍树；页面的“未连接/尚未连接”等状态文字仍保留。
